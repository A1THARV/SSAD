# ---------------------------------------------------------------------------
# MKL / OpenMP CONFLICT — read this before running anything
#
# Anaconda's NumPy links Intel MKL's libiomp5md.dll; PyTorch ships its own,
# different build of the same DLL. With both loaded, importing torch and then
# calling ANY MKL-backed NumPy routine — `a.T @ a`, `np.linalg.eigh`, i.e. every
# line of the PCA path — ABORTS the interpreter with:
#
#     OMP: Error #15: Initializing libiomp5md.dll, but found
#          libiomp5md.dll already initialized.
#
# `src/pipeline/runtime.py` sets KMP_DUPLICATE_LIB_OK=TRUE before torch loads,
# which is the documented-but-unsupported workaround. Intel warns it "may
# silently produce incorrect results", so it is VERIFIED rather than trusted:
# tests/unit/test_runtime.py runs the corpus-covariance kernel in two
# subprocesses — one with torch loaded under the flag, one with NumPy alone —
# and asserts the covariance and its eigenvalues are bit-identical.
#
# Every entry point calls configure_openmp() before importing torch. A script
# that imports torch first will abort, and that is the reason why.
#
# On a non-Anaconda install with a single OpenMP runtime the conflict does not
# arise and the flag is harmless; test_runtime.py skips itself in that case.
